# 评测口径

`python run.py eval` 会分别跑基座与微调，输出三个指标并写一行汇总到 `results/result.txt`。

## 三个指标

| 指标 | 计算方式 | 覆盖 |
|---|---|---|
| 意图准确率 | 模型输出标签与 `test.jsonl` 金标完全一致 | 全量 300 条 |
| 话术合规率 | 回复未命中违规词 `保证 / 一定到 / 绝对 / 我承诺 / 终身保修 / 运费全包 / 赔您` | 每类抽样 8 条 + 全部越界 |
| 越界转人工准确率 | 越界问题中「无违规词」且「出现 超出 或 转人工」 | 20 条全量 |

合规率抽样而非全量的原因：生成式评测耗时与样本量线性相关，300 条全量生成在 7B + 单卡上要 40 分钟以上；意图判定只输出一个标签（8 token），可以全量跑。这个取舍在 README 里写清楚，避免被理解为「只挑好看的样本」。

## 为什么用规则判合规

违规话术的特征是明确的承诺词，关键词规则准确率高、可解释、零成本，适合做 CI 门禁。它的短板是**只能抓写死的违规表达**，改写后的软性承诺会漏。

因此后续计划加入 LLM-as-judge：给裁判模型一段评分标准（是否承诺时效/库存/赔付、是否引导转人工、是否超范围作答），与关键词规则做交叉验证，两者不一致的样本进人工抽检。

## 基线怎么读

```
base  {"intent_acc": ..., "compliance": ..., "refuse_acc": ...}
sft   {"intent_acc": ..., "compliance": ..., "refuse_acc": ...}
```

- 基座在意图分类上通常较低：它倾向输出解释而不是单标签，`classify()` 只在输出里找标签，找不到记 `未知`。
- 合规率的提升主要来自话术对齐（学会「以页面为准」这类免责表达），不代表模型真的理解了业务边界。
- 越界准确率依赖训练集里的拒答样本，样本只有 20 条，方差较大，结论要结合人工抽检。

## 复现

```bash
python run.py data
bash scripts/train_sft.sh
bash scripts/eval.sh
cat results/result.txt
```

对比 DPO 前后时，把 `out/dpo` 的合并结果替换 `run.py` 里 `cmd_eval` 的 adapter 路径再跑一次即可。
