# 数据构造

`python run.py data` 生成三份文件（均不入库，本地可复现）：

| 文件 | 条数 | 用途 |
|---|---|---|
| `data/sft.jsonl` | 2280 | SFT 训练，`system / user / assistant` |
| `data/pref.jsonl` | 790 | DPO 偏好对，`chosen` 合规、`rejected` 违规承诺 |
| `data/test.jsonl` | 300 | 评测集，`user / intent / forbidden` |

## 意图体系

7 类正向意图 + 1 类越界：

```
物流查询 / 退换货 / 发票问题 / 商品咨询 / 优惠活动 / 投诉建议 / 转人工 / 越界
```

每类配 6 条模板（测试集另用 4 条**留出模板**），槽位包括订单号（`10^11 ~ 10^12` 随机）、商品（12 种）、天数（1/2/3/5/7/15）。

## 表面多样性

同一模板前挂 8 种问法前缀（`请问`、`你好，`、`想问下，`、`麻烦问一下，`、`在吗，`、`客服你好，`、`打扰了，` 与空前缀），配合槽位随机，使 280 条/类的问句基本不重复。

> 这是合成数据的常用做法，但**不等于真实分布**：真实工单会有错别字、口语省略、多意图混合。当前版本的结论只在本分布内成立。

## 两类样本

1. **对话样本**：`（system 服务规则, 用户问题）→ 标准话术`，话术里不出现「保证/一定到/终身保修」等承诺。
2. **意图分类样本**：`（分类器 system, 问题 + 可选标签）→ 单个标签`。加这一路的目的是让模型真的学会判断意图，否则评测只能靠话术反推，指标会虚高。

越界样本单独构造：训练集 20 条（`OOS_TRAIN`）、测试集 20 条（`OOS_TEST`），措辞不同，标准回复是「超出服务范围 + 建议转人工」。

## 去重与防泄漏

1. **集合内精确去重**：同一问句只保留一次。
2. **跨集近重复过滤**：字符 5-gram + MinHash（16 排列，4 桶 × 4 行做 LSH 预筛），签名相似度 > 0.75 判为近重复并从训练集移除。
3. **模板级留出**：测试集使用与训练集不同的模板措辞，仅槽位不同不算新样本。

当前配置下跨集过滤丢弃 **0 条**，说明模板留出后训练/测试已无重叠；若把测试模板改回与训练一致，该数字会立刻上升——可以用它做泄漏自检。

```bash
python run.py data
# 去重后与测试集近重复丢弃：SFT 0 条 / 偏好对 0 条
```

## 已知局限

- 数据由模板 + 槽位合成，未使用真实脱敏工单，语义多样性有限。
- 偏好对的 `rejected` 是人工写的违规话术，覆盖的违规类型集中在「承诺时效/库存/价格/赔付」四类。
- 意图标签由构造过程决定（强标注），但同一问题在不同上下文里可能属于多个意图，当前未建模多意图。
